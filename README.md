# ⚓ עוגן CRM — מערכת ההשמה

מימוש **חלק א׳** ממסמך האב: מערכת CRM לרכזי השמה, קובץ HTML יחיד, ללא שלב בנייה, פריסה בגרירה אחת.

---

## הפעלה

- **הרצה מקומית:** פתחו את `index.html` בדפדפן (או הריצו `python -m http.server` בתיקייה).
- **קוד גישה ברירת מחדל:** `1234` (ניתן לשינוי בהגדרות; נעילה לאחר 5 ניסיונות).
- **קישור ראיון למטפלים:** `index.html?mode=interview` — עמוד עצמאי, שתפו בוואטסאפ.
- **פריסה:** גררו את התיקייה ל‑[Netlify Drop](https://app.netlify.com/drop) או דחפו לענף `gh-pages` ב‑GitHub Pages. הכול סטטי + PWA (`manifest.json`).

## נתונים ואבטחה

- אחסון מקומי ב‑`localStorage` (מפתח `ogenCRM3`) — נשמר מיד, עם טיפול ב‑QuotaExceeded.
- הגנות שמומשו (חלק א7): `esc()` בכל הזרקת DOM, `sanitizeDb()` שמסירה `<>` בטעינה/שמירה, `clean()`/`cleanInt()` על פלט הראיון, נעילת PIN, `capActivities()` (200 רשומות), מחיקה רכה (`_deleted`).
- גיבוי/שחזור JSON + ייצוא CSV(Excel)/ICS מההגדרות והדוחות.

## חלק ב׳ — מפת הדרכים אל "חיבור בקליק" (לתכנון, לא מומש)

בהתאם ל‑ב9 במסמך האב. הליבה הנוכחית ממשיכה לרוץ בזמן שהמודולים נבנים לצידה.

**שלב 1 — פלטפורמה דו‑צדדית (MVP)**
- Backend (Node/NestJS או Python/FastAPI) + **PostgreSQL** במקום המסמך היחיד.
- RBAC אמיתי: משפחה / מטפל / רכז / מנהל (מעל ה‑PIN הקיים).
- הרשמת משפחה + שאלון; הרשמת מטפל + פרופיל ומדיה מאובטחת.
- הרחבת חוק הזהב: אשרה בתוקף, אזור חוקי, זמינות — מעל `scoreMatch` הקיים.
- סבבי 5 מועמדים + לייקים + אישור רכז; **הסתרת טלפונים** עד אישור הדדי.

**שלב 2 — AI ותקשורת מתקדמת**
- AI Recruiter לשני הצדדים (הרחבת מנוע הראיון הקיים).
- בדיקת מסמכים (דרכון/אשרה), תרגום בזמן אמת, וידאו, WhatsApp API, כספת מסמכים.

**שלב 3 — מערכת חכמה ולומדת**
- מנועי למידה/הוגנות/חיזוי נטישה עם לולאת משוב על שרידות ההשמה.
- שוק חכם, "התאמה לפני חיפוש", אפליקציות ייעודיות למטפל ולמשפחה.

**עקרונות מנחים:** לבנות על הקיים · מודולרי ומדורג · חוק הזהב מעל הכול · האמון הוא המוצר · הדאטה היא הנכס · הרכז במרכז.
